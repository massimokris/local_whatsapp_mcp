## Standards

- **P1 — Failed revocation disappears from UI but returns after restart.** `backend/internal/service/http.go:135–145` changes `s.cfg.Grants` before persisting, without rollback. A failed settings write removes the agent in memory despite the save error; restart restores its credential from unchanged settings. Disabling sending has the same defect. Persist a candidate configuration before publishing it, and add failure/restart fixtures. Breaches AGENTS.md's recoverable configuration failures and credential-revocation fixtures requirement.
- **P2 — Startup failures lose their actionable explanation.** `native/Sources/LocalWhatsAppCore/HelperRuntime.swift:29–33` discards service stderr. Corrupt settings, denied Keychain access, or an occupied port exits with a specific diagnostic, but the app repeatedly presents generic not-running instructions. Capture bounded, safe startup errors and expose them through the runtime.
- **P2 — Required entry-point documentation remains unupdated.** AGENTS.md and README.md still assert that no implementation or build command exists. Add verified commands and current status without claiming live WhatsApp/client compatibility.

Baseline judgment, not a documented-standard violation: the durable-write implementation is duplicated between cloud OAuth and service persistence; a shared utility would keep durability fixes consistent.

## Spec

- **P1 — Identity migration makes chat removal ineffective.** SPEC.md requires immediate removal and consistent verified aliases. AppModel copies raw saved IDs; the picker toggles only current catalog IDs. Upstream LID-to-PN migration deletes the LID catalog row. Selecting then deselecting PN, or clearing visible rows, leaves the invisible selected LID, still authorizing PN through verified alias resolution. Canonicalize verified selection groups and remove every alias when deselecting.
- **P1 — Relaunch after an app crash leaves an unowned backend that Quit cannot stop.** HelperRuntime launches the service without an owner-lifetime channel. Native termination leaves it running; relaunch tracks a replacement that exits on the lock, while controls reach the old process. Quit stops only the tracked replacement. Add owner-lifetime shutdown or safe adoption.
- **P2 — Configuration failures lose their recovery explanation.** The same discarded startup stderr prevents the specific recovery action required by SPEC.md.

No confirmed scope creep. Actual provider login remains unverified, rather than a missing implementation finding.

- Engine progress events occur for live traffic too. Present truthful synchronization/freshness state without suggesting complete historical import.
