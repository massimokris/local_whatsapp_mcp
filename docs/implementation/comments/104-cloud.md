## Historical setup and protocol

The removed **Connect cloud agent** flow required confirmed scope, ngrok (the default) or a named Cloudflare Tunnel, a stable public hostname, and a ten-minute, single-use invitation. A local agent installed/configured the provider and invoked the bundled helper with the invitation on stdin. Configuration retained credential references; secrets were imported privately into Keychain. The app owned provider startup restoration, retries, and shutdown. Local access required neither a tunnel nor a provider account.

For ngrok, the helper imported existing configuration or opened the provider dashboard and a native secure dialog for the user to transfer the authtoken outside agent conversation. For Cloudflare, the agent completed browser login, created the named tunnel and DNS route, and supplied a credentials-file path for private import. Normal operation used the Keychain copy; provider-managed login files remained the provider's responsibility. Background authentication failures reported recovery instead of opening login windows. ngrok request inspection was disabled; Cloudflare ingress ended in a catch-all 404.

After public discovery and unauthenticated-denial checks, the helper opened a short-lived setup session. Hosted-client OAuth had to finish in that same browser, without a LocalWhatsAppMCP account or additional native approval. ChatGPT was the default client; other clients required their documented client ID and exact redirect URI. Expired sessions required fresh instructions.

The private Unix setup route bound a read-only grant to the expected client and redirect. A random loopback URL posted a one-use handoff secret to the public HTTPS bootstrap endpoint, keeping it out of URL queries and persistent logs. Bootstrap established a Secure, HttpOnly cookie. Authorization bound the actual client, exact redirect, resource audience, S256 challenge, and request state to that session; a CSRF-protected Connect submission consumed it. The OAuth manager used authorization code/PKCE, digest-only durable token records, and rotating refresh tokens. Every exchange, refresh, and resource request rechecked the active grant; revocation used the ordinary app controls. Sending started disabled. Private control and provider administration were absent from the public listener. A validated native URL scheme existed, but unsolicited callbacks could not grant access. The archive/session stayed on the Mac, with cloud access unavailable during sleep or after Quit.

Removed implementation paths included `backend/internal/cloud/extension.go`, `backend/internal/cloud/oauth_flow.go`, and `backend/cmd/localwhatsappmcp/cloud.go`. The earlier [pairing research](../../research/agent-pairing.md) records the source evidence and unanswered questions resolved by this implementation. Client contracts consulted on 2026-10-23 included [OpenAI's plugin authentication documentation](https://developers.openai.com/plugins/build/auth) and [ChatGPT's OAuth client metadata](https://chatgpt.com/oauth/client.json). Synthetic fixtures did not authenticate a real provider, establish DNS, or reload a hosted client.
