# Installation and acceptance

The current contract is local-only MCP access, revised on 2026-10-23. The original **0.1.0** implementation was packaged for installation testing before that revision. That checked build is Apple silicon (`arm64`), ad-hoc signed, with a macOS 13 deployment target verified in all three Mach-O executables. Runtime checks ran on macOS 26.5.2; neither Intel nor every supported macOS version has been exercised. Developer ID signing and notarization require the owner's release credentials.

## Install and first use

1. Quit any running copy, open `dist/LocalWhatsAppMCP-0.1.26-arm64.dmg`, and drag **LocalWhatsAppMCP.app** to **Applications**, replacing the existing copy. This installer contains the current **0.1.26 (27)** build. A ZIP and standalone app are also available in `dist/`; use the [build guide](building.md) to rebuild. The installed copy was not replaced automatically. An unlinked account opens directly to **Connect WhatsApp**; a saved authenticated session opens the overview while sync resumes.
2. Scan the displayed QR from WhatsApp's **Linked Devices** screen on your phone. Successful linking returns automatically to the overview without a Continue click. Content delivered during setup is captured immediately; agent access waits for your scope choice.
3. Choose **Continue with all chats** or **Select specific chats**. All chats includes future conversations. Selected chats includes only your saved selections; its search and Select all operate across every matching result.
4. Open **Local MCP** from the overview. With no saved connections, **Connect your agent** offers **Copy instructions** and inline **Do it manually**. Copy instructions creates and copies a ten-minute, one-use HTTP invitation; give it to your agent to exchange and configure its own MCP client. Do it manually creates a connection and reveals inline **URL** and **Token** rows with copy icons for the full values. The token fills the available width and truncates only when needed. Saved connections appear under **Local MCP** as home-style cards with last-request age and message-sending status. Expand a card to **Delete connection**, toggle **Allow message sending**, or reveal **Credentials** with its **Show** button using the same inline URL/token rows. **Add new connection** opens setup again. New connections receive the first unused **Connection N** name and start with sending disabled. Every connection card uses the `apple.terminal` SF Symbol (with `terminal` as the fallback if unavailable). Existing names are preserved. Deletion revokes that credential while retaining client configuration and other connections.
5. Use **Choose** in the **Choose connected chats** row below the expanded WhatsApp card's disconnect controls to change confirmed scope. Its subtitle reports the saved scope's chat count; the collapsed card has a right chevron. Settings contains **Start at Log In** with a green enabled switch and **Quit**, without the Local MCP card. Clicking outside keeps the window open; focusing another app lets that app cover it, and it does not follow every Space. Native close hides it while background sync and local MCP access keep running; the menu bar reopens it. Quit stops the app-owned processes.
6. Expand the WhatsApp card to **Disconnect** this linked device. Confirming stops syncing and signs out while preserving your local archive and selections. Background restart and wake leave it disconnected. Opening the app again prepares a new QR for a phone scan; an unfinished sign-out instead offers **Retry disconnect**.

The current source includes the simplified connection UI, direct manual URL/token configuration, generic one-use HTTP pairing, and per-agent permissions, with automatic linked-account routing and normal window layering. Builds through **0.1.14 (15)** used the former client-specific setup helper; see the generic-pairing verification below for the replacement. The historical WhatsApp-only screenshots and package checks below predate MCP management; client installation/reload still requires the live checks listed here.

The archive and configuration live in `~/Library/Application Support/LocalWhatsAppMCP/`. App replacement preserves them. App-managed secrets live in the private `credentials.db` SQLite database; the upstream WhatsApp session has its own protected store. Existing excluded content can remain on disk, while current server policy denies access. Removing a chat does not promise to erase previously captured content or recall content already given to an agent.

The SQLite upgrade does not read Keychain. It creates a new checkpoint key, expiring earlier checkpoints and temporary attachment links, and rotates credentials for configured helper connections while retaining their IDs and permissions. Back up `credentials.db` with `settings.json`; after migration, missing or corrupt credentials require recovery instead of regeneration. The database uses owner-only file permissions and no application-level encryption.

MCP is available only on this Mac through loopback HTTP. There is no tunnel, external endpoint, provider setup, or browser authorization. Both manual setup and one-use HTTP pairing give each agent its own credential for independent revocation and sending permission, managed from the local MCP screen. Mac sleep or quitting the app makes local access unavailable; the app does not keep the Mac awake.

## Live installation checks

QR generation has been verified. The following checks remain for the user's account. No real message was read or sent during the build.

- **Link and capture:** scan the QR, observe catalog/history arriving, interrupt setup and reopen, then confirm that agent access remains unavailable until scope is saved. Available history may be partial.
- **Scope:** select a test conversation, ask an agent to find/read it, and verify that another conversation is absent. Remove the selected chat and repeat reading and cached-attachment access. Add a new group and compare All chats with Selected chats.
- **Agents:** configure one local client manually using its URL and access token, and another through generated instructions. Reopen the manual connection's details and verify the same credential is available. Verify reading, enable sending for only one, send a test message with a fresh request ID, and revoke one connection while keeping the other usable. Inspect uncertain sends before retrying with a different ID.
- **Attachments:** retrieve a known small file, a file larger than one MCP chunk, and an older unavailable file. Expect content or an explicit recovery/unavailable result. Phone-mediated recovery depends on the phone retaining the file and responding.
- **Lifecycle:** close the panel, sleep/wake, reopen, and Quit. Confirm the app reports recovery honestly and that Quit stops its service and engine. Enable Start at Log In using any required macOS approval.
- **Disconnect:** confirm sign-out in the expanded WhatsApp card, verify this linked device disappears on the phone, and reopen the app to confirm it stays disconnected. Reconnect explicitly and verify saved scope and archived messages remain. Live linked-device logout has not been exercised by the synthetic checks.

The agent now configures its own client using the returned Streamable HTTP URL and bearer token. The app no longer installs Codex/Claude configuration or supplies a stdio bridge. The unchanged UI still lists the former client choices, but each non-manual choice produces generic instructions. Actual client configuration and reload remain live acceptance checks.

## Recovery

Preserve the application data directory before investigating storage errors. A missing or invalid confirmed configuration blocks access; restore the matching settings instead of deleting them to reopen the archive. If client configuration fails after a successful exchange, the agent should finish configuring with its saved access token. If it failed to save the token, remove that connection and create a fresh invitation; a redeemed code cannot be replayed. Existing configurations invoking removed `setup`, `headers`, `doctor`, or `stdio` commands need reconfiguration. Existing grants and their permissions are preserved; the app does not rewrite client files.

If WhatsApp revokes the linked device, reconnect from the app. No history-completeness claim is implied by a ready status or recent event timestamp.
